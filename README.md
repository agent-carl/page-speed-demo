# Page speed demo: the same page, before and after

A landing page for a **fictional** coffee roaster, built twice:

- [`before/`](https://agent-carl.github.io/page-speed-demo/before/): the way many small business sites are built. Full-size camera photos, Bootstrap and Font Awesome for a few elements, jQuery and a JS bundle in `<head>`, three font families in fifteen weights, images without dimensions, a promo bar injected by a script.
- [`after/`](https://agent-carl.github.io/page-speed-demo/after/): the same page, looking the same, optimized.

Case study: https://agent-carl.github.io/page-speed-demo/
Sample audit report: https://agent-carl.github.io/page-speed-demo/report/

## Results

Google PageSpeed Insights, mobile, 11 October 2026.

| | Before | After |
|---|---|---|
| Performance | 66 | 97 |
| Largest Contentful Paint | 26.6 s | 2.4 s |
| First Contentful Paint | 3.3 s | 0.8 s |
| Page weight | 4.8 MB | 34 KB |
| Render-blocking files | 6 | 0 |
| Accessibility | 85 | 100 |
| SEO | 91 | 100 |

## What changed

1. Images resized to their displayed size and served as AVIF/WebP with `srcset`; below-the-fold images lazy-loaded.
2. The hero image preloaded with high priority.
3. Unused CSS/JS libraries removed, the page's own CSS (about 2.5 KB) inlined, the icon font replaced by inline SVG.
4. One font family in two weights, loaded without blocking the first paint.
5. Image dimensions set, the promo bar rendered in HTML instead of being injected later.
6. Contrast, heading order, main landmark and meta description fixed.

The images are generated by [`tools/make_images.py`](tools/make_images.py) (procedural pictures, no stock photos). It also shows the resizing and encoding step. Real photos keep more detail, so savings on a real site are usually smaller.
